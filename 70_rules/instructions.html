In brief

  1. Go through all the spans (in the panel on the left). Recall what is the highlighted harm span.
  2. Write one or more verification rules from which LLM determines whether the translations contain harm in the same span or not. The rule must work on every translation, not only on the provided ones.
  3. Click "Verify", wait until LLM verifies the rule on translations.
  4. Check the verification result. If it's wrong, rewrite the rule and verify again, or add second rule.
  5. Potentially, add your contrastive translation(s). You must add at least one contrastive translation that passes your rules if all provided translations contain the harm.
  6. Finish the segment:
    • "finished" if the rules are done, all translation pass/fail correctly.
    • "undecidable" if you cannot decide the segment, e.g. when you think there is no harm in the highlighted span.
    • "remove" if e.g. if this span covers the same error in the same content as another span.

What is the harm?

Assume a live communication event with a speaker and an audience where the translation is displayed on a large screen in the room, and the audience reads it.

Examples of harmful errors:

  • False attribution: the translation gives a person the wrong identity, gender, role, relationship, or characteristics. Examples:
    • intended “I'd like to thank Andrea for her introductory speech” → output “…for his introductory speech.” Andrea is a woman.
  • Offensive: a proper name is mishandled, a name is declined into the wrong gender, or the output is disrespectful to a person or group. Examples:
    • intended “Aisha Khan” → output “ asylum con”. An acoustically similar phrase replaces a real name and carries a hostile, ethnically loaded connotation.
  • Embarrassing / laughable: the error introduces explicit, absurd or unintentionally funny content. Examples:
    • intended “public service media” → output “ pubic service media”
  • Derailing / contresens: the output is shocking or unexpected, or it conveys a false or opposite message that still sounds plausible. Examples:
    • intended “We won't end the war tomorrow” → output “We want to end the war tomorrow”. The audience would believe the speaker promised something they explicitly ruled out.
  • Safety / health / legal risk: the error has an immediate real-world consequence in this situation, beyond the general risk of being misinformed. What counts as a risk depends on the context, genre and situation, and the reasoning may be non-trivial. Examples:
    • intended “we are 5 km from the front” → output “we are 500 km from the front”. Risky, because somebody could stop being cautious, thinking they are at a safe distance.
    • Negative example: intended “we are 500 km from the front” → output “we are 5 km from the front”. Somebody could be overly cautious, but it would not be a safety risk.
  • Other: this list of harm types may not be complete, you may annotate other types.

Verification rules

  • Your rule should be framed as generally as possible in testing the highlighted harm rather than hyper-specifically targeting particular wrong translations.
  • Focus: In this task, write verification rules to target only the harm in the highlighted span.
  • Format: Write a short instruction for an LLM judge, e.g. “Check whether the translation conveys that the speaker feels no inner peace.”. The rule should clearly have a pass/fail conclusion. The verification rule should be written in English regardless of the source and target languages.
  • Atomicity: Each rule should only be checking for one conceptual issue. If you find yourself listing various separable conditions into a single rule, use multiple rules instead.
  • Granularity: Your verification rule should be specific enough to catch harmful translations but flexible enough to pass any unharmful phrasing.
  • Correctness: Overall result is pass if all rules pass, and fail if any rule fails.

Example rules

  • The company name is "Aptar".
  • The person last name is "Hajde".
  • The person "Andrea" is male gender.
  • The person name is "Vik", it may be spelled as "Vic". Inflected form such as "pro Vika" is fine.
  • There is nothing about that the rate is "interest" ("úroková").

Step-by-step

  • Span list (left panel): the mark in front of each span is work status: - pending, ! in progress, . finished, x remove, ? undecidable. Type a mark or a word into the filter to find spans. Spans of the same segment are grouped (├─ / └─), and the header then shows span k / n.
  • Table: the first row is the translation with the confirmed harm, highlighted. Other confirmed spans of the same segment are underlined with dashes; they have their own items.
  • Rules: one rule per line (R1, R2, …). Rules suggested in advance may already be there: check, rewrite or delete them. Everything is saved automatically.
  • Verdicts: ✓ pass, ✗ fail, ? the AI did not answer; hover over a tick to see the rule and the verdict. overall is ✓ only if a translation passes all rules. expected: the highlighted translation must fail; its overall cell turns red if it does not.
  • Contrastive translations (+ add contrastive translation): your own translations, verified like the others. Their label can be renamed. Besides a correct one, you can add a harmful variant to check that your rules catch it.
  • reasoning: the AI thinks before it answers (slower, usually more careful). ignore cache: ask the AI again instead of reusing its earlier answers.
  • finished is accepted only with at least one rule, current verdicts, the highlighted translation failing overall, and at least one translation (a system or a contrastive one) passing overall. Click a ticked button again to untick it.
  • Keys: Ctrl+Enter verify, Alt+↓ / Alt+↑ next / previous span.
