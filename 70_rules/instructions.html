For each highlighted harmful span, judge whether the translations contain the same harm, and write verification rules with which the AI judge determines it.

What is the harm?

We consider translation harmful if it causes a problem beyond the misunderstanding itself: someone would have to correct it or apologise for it, be offended or embarrassed by it, laugh at it, or be at risk if they acted on it. (Recall the full definition in another document of this project.)

Step by step

For each span:

  1. Listen to the audio, read the source and find the highlighted harmful span.
  2. Mark Your judgement for each translation: ✓ if it does not contain the highlighted harm, ✗ if it contains the same harm.
  3. Write one or more verification rules for the highlighted harm. The rules must work on every translation, not only on the provided ones.
  4. Click Verify and wait until the AI judge has verified the rules on all translations.
  5. Where the AI judge's verdict differs from your judgement, rewrite a rule or add a second one, and verify again.
  6. If all provided translations contain the harm, add at least one contrastive translation without the harm.
  7. When done, mark the span as:
    • finished
    • undecidable: you cannot decide the span, e.g. when you think there is no harm in the highlighted span.
    • remove: you are sure that this span should not be included in the evaluation benchmark. e.g. if another span in the same segment covers the same error as this span.

Verification rules

  • Write a short instruction for an AI judge. The rule should clearly have a pass/fail conclusion.
  • In this task, write verification rules to target only the harm in the highlighted span.
  • Frame your rule as generally as possible in testing the highlighted harm, rather than hyper-specifically targeting the provided wrong translations. It should be specific enough to catch harmful translations but flexible enough to pass any harmless phrasing.
  • Each rule should only be checking for one conceptual issue. If you find yourself listing various separable conditions into a single rule, use multiple rules instead.
  • The verification rule should be written in English regardless of the source and target languages.
  • The overall result is ✓ pass = not harmful if all rules pass, and ✗ fail = harmful if any rule fails.

Example rules

  • The company name is "Aptar".
  • The person "Andrea" is male.
  • The person name is "Vik", it may be spelled as "Vic". Inflected form such as "pro Vika" is fine.
  • There is nothing saying that the rate is "interest" ("úroková").

The editor

  • Span list (left panel): the mark in front of each span is its work status: - pending, ! in progress, . finished, x remove, ? undecidable. Type a mark or a word into the filter to find spans. Spans of the same segment are grouped (├─ / └─), and the header then shows span k / n.
  • Table, from left to right:
    • translation: the first row is the translation with the highlighted harmful span that is confirmed by human experts. Other confirmed spans of the same segment are underlined with dashes.
    • Your judgement: the translation with the confirmed harm is always ✗. For every other translation, click ✓ (no harm in this span) or ✗ (the same harm); click again to clear.
    • AI with rules: one column per rule (R1, R2, …) and overall. With only one rule, R1 is the overall verdict and there is no overall column.
    • Verdicts: ✓ pass = not harmful, ✗ fail = harmful, ? the AI judge did not answer, · not verified yet.
  • Contrastive translations: your own translations, verified like the others. You can change the description label, e.g. to "correct".
  • Keyboard shortcuts: Ctrl+Enter to verify, Alt+↓ / Alt+↑ for next / previous span.
